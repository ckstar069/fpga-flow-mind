## 产品一句话定位

`fpga-flow-mind` 是一个本地桌面端 FPGA 阶段实现理解与可视化 Agent，帮助用户快速理解由 AI Agent 分阶段推进生成的 FPGA 业务项目在各阶段实际实现了什么。

## 目标用户

使用 `ai_project_template` 创建业务项目、并借助 AI Agent 从 L0/L1/... 分阶段推进至 RTL 的 FPGA 开发人员或项目负责人。

这些用户面临的核心问题是：AI Agent 生成代码体量大、跨文件、跨阶段、跨语言，用户无法逐行审核所有代码来确认实现方向是否偏离预期。

## 真实业务场景

1. 用户使用 `ai_project_template` 创建业务项目
2. 从 `urban_wireless` 导入所需模块
3. AI Agent 按模板流程从 L0 → L1 → ... → L6 → RTL 分阶段推进
4. 每阶段产生大量 Python、Verilog、测试、文档和配置
5. 用户需要确认：当前阶段实际实现了什么？是否与预期一致？
6. 用户打开 `fpga-flow-mind`，选择阶段，查看结构图、数据流图、时序图
7. 用户点击节点追溯源码证据，围绕具体实现继续追问

## 用户核心痛点

- **代码体量过大**：单阶段可能涉及数十个文件，人工通读不现实
- **跨阶段、跨语言**：前期为 Python，后期转为 Verilog/RTL，理解难度递增
- **临场画图不可持续**：开发 Agent 临时画图效果好，但结果不稳定、不可持久、不可对比
- **证据与结论脱节**：现有工具要么只做静态提取（缺乏语义理解），要么只做自由文本生成（缺乏证据约束）
- **不确定性被隐藏**：AI 生成代码中可能存在推断成分，但现有方式不标注不确定项

## 产品应提供的理解能力

`fpga-flow-mind` 应帮助用户获得以下理解：

- **workspace understanding** — 业务项目整体结构、阶段分布
- **stage understanding** — 单个阶段的模块组成、接口关系、实现意图
- **dataflow understanding** — 数据从哪里来、经过什么变换、流向哪里
- **timing understanding** — 时序/流水关系、latency、握手信号
- **semantic claims** — 对实现的具体语义结论（公式、信号映射、模块职责）
- **evidence traceability** — 每个结论可追溯到源码文件和行号范围
- **uncertainty expression** — 不确定、推断、冲突项被显式标注
- **grounded Q&A** — 基于证据继续追问，而非一次性报告

## MVP 范围

首个最小可用闭环聚焦：

```text
单业务项目
  + 单选中阶段
  + 三类核心视图（结构图、数据流图、时序/流水图）
  + 证据回链
  + 追问能力
```

MVP 内必须支持：

1. 打开一个真实业务项目（`ai_project_template` 创建）
2. 识别阶段目录和相关上下文
3. 读取 Python/Verilog/docs/tests/config
4. 生成至少三类视图
5. 每个主要节点或结论可回链到源码证据
6. 对证据不足处明确标注 `unknown` 或 `inferred`
7. 支持用户围绕某个图节点继续追问
8. 产物可持久化并再次打开

## 非目标

当前阶段明确不做：

- **审计器** — 不替用户判断代码正确性
- **PASS/HOLD 决策工具** — 不做自动通过/拒绝判定
- **通用静态分析器** — 不做跨任意代码库的分析工具
- **JSON viewer / Markdown report viewer** — 用户看到的不应是原始产物格式
- **通用聊天应用** — 不是无上下文的自由对话工具
- **云端优先系统** — 不是以服务端计算为主的 SaaS
- **团队协作平台** — 不做多人协作、评论、审批流程
- **规则引擎** — 不做基于固定规则的检查
- **大而全可视化平台** — 不追求覆盖所有可能的图类型
- **自动修复或自动改写** — 不修改目标 FPGA 项目

## 成功标准

MVP 成功不以"系统替用户裁决"为标准，而以"用户能否更快读懂项目"为标准。

通过条件：

- 用户不需要通读全部代码，也能理解该阶段做了什么
- 图中有明确输入、处理、中间结果、输出
- 图不是一堆孤立方块
- 主要说明有源码证据
- 不确定项被显式表达
- Python 阶段与 RTL 阶段都能纳入同一理解框架
- 结果可持久化并再次打开
- 用户可以继续提问，而不是只能看一次性报告

## 与相关项目的关系

| 项目 | 关系 | 说明 |
|------|------|------|
| `ai_project_template` | 上游模板 | 业务项目的创建来源，`fpga-flow-mind` 应能识别其目录结构和阶段约定 |
| `urban_wireless` | 上游模块库 | 业务项目从中导入模块，`fpga-flow-mind` 应能识别外部模块引用 |
| `fpga_project_*` | 分析目标 | `fpga-flow-mind` 读取并理解的项目，但**只读、不修改** |

## 安全边界

分析业务项目时：

- 目标项目**只读**
- 不修改 `fpga_project_*`
- 不运行 Vivado
- 不运行 synthesis / implementation / bitstream
- 不默认运行目标项目脚本
- 不把输出写回目标项目目录
- 优先使用临时目录或 app-owned 目录

## 明确声明

`fpga-flow-mind` **不是**：

- 审计器
- PASS/HOLD 工具
- 通用静态分析器
- JSON viewer
- Markdown report viewer

它的定位是**理解与可视化工具**，帮助用户通过图、解释和证据更快理解 FPGA 阶段实现，所有判断和决策权保留给用户。
