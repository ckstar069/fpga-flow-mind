# Story: 查看数据流图

---
status: draft
updated: 2026-06-11
---

## 用户目标

作为 FPGA 开发人员，我希望看到选中阶段的数据流图，以便理解数据从哪里来、经过什么变换、流向哪里。

## 业务背景

数据流图回答"该阶段如何处理数据"：输入数据经过哪些运算/变换步骤，中间结果如何传递，最终输出是什么。这对于理解算法的实际实现路径至关重要。

## 前置条件

- ImplementationUnderstanding 已生成
- dataflow_view 部分已填充

## 触发入口

用户在理解结果概览面板中点击"查看数据流图"按钮，或在结构图视图中切换到数据流图标签页。

## 主流程

1. 用户触发数据流图展示
2. 系统从 ImplementationUnderstanding 中提取 dataflow_view 数据
3. 系统生成可视化规范
4. 系统渲染数据流图
5. 用户与数据流图交互（点击查看节点详情）

## 功能点清单

### VD-001 触发数据流图展示

- **用户动作**：用户点击"查看数据流图"按钮
- **系统必须**：
  - 切换到数据流图视图面板
  - 显示加载状态（如有必要）
  - 如 dataflow_view 未生成，提示"数据流信息未生成"
- **成功结果**：数据流图视图面板展示
- **失败表现**：无数据时显示空状态提示
- **evidence 要求**：不需要
- **MVP 必须**：是

### VD-002 节点类型定义

- **系统动作**：定义数据流图中支持的节点类型
- **系统必须**：数据流图包含以下节点类型：
  - **数据源节点**（Source）：原始输入数据、参数、常量
  - **变换节点**（Transform）：数据运算/处理步骤（如 FFT、滤波、乘法）
  - **中间结果节点**（Intermediate）：变换产生的中间数据
  - **汇聚节点**（Sink）：最终输出结果
  - **条件/控制节点**（Control）：影响数据流向的条件判断或状态控制
- **成功结果**：节点类型清晰可区分
- **失败表现**：无
- **evidence 要求**：每个节点必须携带 evidence_refs
- **MVP 必须**：是

### VD-003 边类型定义

- **系统动作**：定义数据流图中支持的边类型
- **系统必须**：数据流图包含以下边类型：
  - **数据边**（DataFlow）：数据从上游流向下游
  - **控制边**（ControlFlow）：控制信号影响执行路径
  - **依赖边**（Dependency）：节点间的计算依赖关系
- **成功结果**：边类型清晰可区分
- **失败表现**：无
- **evidence 要求**：每条边必须携带 evidence_refs
- **MVP 必须**：是

### VD-004 节点携带 evidence_refs

- **系统动作**：确保每个数据流节点都有 evidence 关联
- **系统必须**：
  - 每个变换节点携带 `evidence_refs`，指向实现该变换的代码位置
  - 每个数据源/汇聚节点携带 `evidence_refs`，指向接口/端口定义
  - 用户点击节点时可查看关联的 evidence 列表
- **成功结果**：节点与 evidence 的关联可查询
- **失败表现**：无 evidence 关联的节点标注为 `unknown`
- **evidence 要求**：每个节点至少有一个 evidence_id 或标注为 `unknown`
- **MVP 必须**：是

### VD-005 边携带 evidence_refs

- **系统动作**：确保每条数据流边都有 evidence 关联
- **系统必须**：
  - 每条数据边携带 `evidence_refs`，指向信号赋值或数据传递的代码位置
  - 用户点击边时可查看关联的 evidence 列表
- **成功结果**：边与 evidence 的关联可查询
- **失败表现**：无 evidence 关联的边标注为 `inferred`
- **evidence 要求**：每条边至少有一个 evidence_id 或标注为 `inferred`
- **MVP 必须**：是

### VD-006 数据流图渲染

- **系统动作**：将 dataflow_view 数据渲染为可视化图
- **系统必须**：
  - 展示数据从源头 → 变换步骤 → 最终输出的流向
  - 数据流向从左到右（输入在左，输出在右）
  - 变换步骤按执行顺序排列
  - 不同节点类型使用不同的视觉样式
  - 数据边使用带箭头的实线
  - 控制边使用带箭头的虚线
  - 节点标签显示运算/数据名称
  - 节点旁标注置信度指示器
- **成功结果**：用户可直观理解数据变换路径
- **失败表现**：渲染失败时显示"无法渲染数据流图"
- **evidence 要求**：渲染数据来自 dataflow_view 中的 evidence_refs
- **MVP 必须**：是

### VD-007 空视图处理

- **系统动作**：当 dataflow_view 无数据时处理
- **系统必须**：
  - 显示空状态提示"未识别到数据流"
  - 提示可能原因
  - 提供"重新收集证据"的入口
- **成功结果**：用户了解无数据流数据的原因
- **失败表现**：无
- **evidence 要求**：不需要
- **MVP 必须**：是

### VD-008 证据不足处理

- **系统动作**：当部分数据流节点或边 evidence 不足时处理
- **系统必须**：
  - evidence 不足的节点以降级样式展示
  - 标注为 `unknown` 的节点显示"?"标记
  - 用户悬停时显示"数据流向推断，证据不足"提示
- **成功结果**：用户了解哪些数据流缺乏证据
- **失败表现**：无
- **evidence 要求**：unknown 节点仍应尽可能关联 source path
- **MVP 必须**：是

### VD-009 冲突证据处理

- **系统动作**：当存在冲突 evidence（如代码与文档描述的数据流不一致）时处理
- **系统必须**：
  - 冲突节点/边以警示样式展示
  - 用户点击时显示冲突详情
  - 不自动裁决哪一方正确
- **成功结果**：用户了解存在冲突的证据
- **失败表现**：无
- **evidence 要求**：冲突详情应列出冲突的 evidence_ids
- **MVP 必须**：是

### VD-010 节点点击交互

- **用户动作**：用户点击数据流图中的节点
- **系统必须**：
  - 高亮选中节点及其上下游路径
  - 显示节点详情面板：名称、类型、描述、运算说明、evidence 列表
  - 提供"查看证据"按钮
  - 提供"追问"按钮
- **成功结果**：用户可深入了解数据变换的 evidence 和上下文
- **失败表现**：无 evidence 时提示"该节点暂无关联证据"
- **evidence 要求**：节点详情必须展示 evidence_id、source_path、line_range
- **MVP 必须**：是

## 输入

| 输入项 | 来源 | 类型 |
|--------|------|------|
| implementation_understanding.json | story-generate-understanding 输出 | 结构化数据 |
| evidence_index.json | story-collect-evidence 输出 | 结构化数据 |

## 输出

| 输出项 | 类型 | 说明 |
|--------|------|------|
| 数据流图可视化 | UI 渲染 | 数据源头、变换步骤、流向的图形展示 |
| 节点详情面板 | UI 状态 | 选中节点的详细信息 |

## 异常 / 空状态

| 场景 | 处理 |
|------|------|
| dataflow_view 为空 | 显示"未识别到数据流"，提供重新分析入口 |
| 渲染失败 | 显示"无法渲染数据流图"，提供重试按钮 |
| 所有节点均为 unknown | 显示"证据不足，无法确定数据流" |
| 存在冲突节点 | 以警示样式展示，点击显示冲突详情 |

## 证据与追溯要求

- 每个节点必须携带 evidence_refs
- 每条边必须携带 evidence_refs
- 用户点击节点/边后，必须能查看到对应的 source_path 和 line_range

## 不确定性表达要求

- `unknown` 节点以降级样式展示
- `inferred` 边以虚线展示
- `conflicting` 节点/边以警示样式展示
- 所有不确定项必须在图中可见

## MVP 验收标准

- [ ] 数据流图展示数据从源头到输出的完整流向
- [ ] 节点类型可区分（Source/Transform/Intermediate/Sink/Control）
- [ ] 边类型可区分（DataFlow/ControlFlow/Dependency）
- [ ] 每个节点携带 evidence_refs，可点击查看详情
- [ ] 每条边携带 evidence_refs
- [ ] 空视图有恰当提示
- [ ] 证据不足的节点以降级样式展示
- [ ] 冲突节点以警示样式展示
- [ ] 不允许将图做成自由文本拼接或 JSON viewer

## 非目标

- 不追求逐信号级别的完整数据通路
- 不做交互式拖拽编辑
- 不做 3D 可视化或动画
- 不把数据流图做成静态 Markdown 报告
