# Story: 选择阶段

---
status: draft
updated: 2026-06-11
---

## 用户目标

作为 FPGA 开发人员，我希望从 workspace 中选择一个具体阶段，以便聚焦于该阶段的实现理解。

## 业务背景

业务项目包含多个阶段（如 L0、L1、...、L6、RTL），每个阶段的代码、语言和实现目标不同。用户需要选择单个阶段进行深入分析，而非一次性处理所有阶段。

## 前置条件

- workspace 已成功打开并生成 workspace profile
- workspace profile 中包含至少一个候选阶段

## 触发入口

用户在 workspace 概览面板中点击某个阶段卡片或列表项。

## 主流程

1. 用户查看阶段列表
2. 用户选择一个阶段
3. 系统验证阶段有效性
4. 系统准备阶段上下文
5. 系统展示阶段概览
6. 系统进入证据收集准备状态

## 功能点清单

### ST-001 阶段列表展示

- **系统动作**：在 workspace 概览面板中展示候选阶段列表
- **系统必须**：
  - 每个阶段显示名称（目录名）
  - 每个阶段显示文件数量统计（代码文件数、测试文件数、文档数）
  - 阶段按自然顺序排列（如 L0 → L1 → ... → RTL）
  - 不可用的阶段（空目录、无代码文件）以灰色或降级样式展示
- **成功结果**：用户可清晰看到所有阶段及其基本状态
- **失败表现**：无阶段时展示空状态提示
- **evidence 要求**：每个阶段的 source path 应关联展示
- **MVP 必须**：是

### ST-002 单阶段选择

- **用户动作**：用户点击一个阶段项
- **系统必须**：
  - 记录用户选中的阶段
  - 高亮显示选中阶段
  - 只允许同时选中一个阶段（单选模式）
  - 触发阶段上下文准备流程
- **成功结果**：阶段被选中，系统开始准备该阶段的上下文
- **失败表现**：点击不可用阶段时提示"该阶段无可分析内容"
- **evidence 要求**：不需要
- **MVP 必须**：是

### ST-003 阶段有效性验证

- **系统动作**：验证选中阶段是否包含可分析的内容
- **系统必须**：
  - 检查阶段目录是否存在且可读
  - 检查阶段目录下是否存在可识别的代码文件（Python、Verilog）
  - 检查阶段目录下是否存在文档或测试文件（可选，作为辅助上下文）
- **成功结果**：阶段通过验证，继续准备上下文
- **失败表现**：
  - 目录不存在或不可读：提示"无法读取该阶段目录"
  - 无代码文件：提示"该阶段未找到可分析的代码文件，是否继续？"
- **evidence 要求**：验证结果应记录 source path
- **MVP 必须**：是

### ST-004 阶段上下文准备

- **系统动作**：收集选中阶段及其相关上下文
- **系统必须**：
  - 收集阶段目录下的所有相关文件列表
  - 识别并关联上游阶段的接口约定（如有，如该阶段依赖前一阶段的输出定义）
  - 识别外部模块引用（如 `urban_wireless` 的导入）
  - 生成阶段上下文摘要（文件列表、语言分布、外部依赖标识）
- **成功结果**：阶段上下文已准备完毕，可进入证据收集
- **失败表现**：上下文准备失败时提示"无法准备阶段上下文"，允许用户重试
- **evidence 要求**：文件列表中的每个文件应包含 source path
- **MVP 必须**：是

### ST-005 阶段概览展示

- **系统动作**：展示选中阶段的概览信息
- **系统必须**：
  - 显示阶段名称和路径
  - 显示文件列表（可按类型分组：代码、测试、文档、配置）
  - 显示外部依赖标识（如有）
  - 显示"开始分析"按钮，触发 evidence 收集
- **成功结果**：用户可确认阶段内容并准备开始分析
- **失败表现**：无内容时显示空状态提示
- **evidence 要求**：文件列表应关联 source path
- **MVP 必须**：是

### ST-006 阶段缺失处理

- **系统动作**：当 workspace 中缺少预期阶段时处理
- **系统必须**：
  - 列出已识别的阶段
  - 对缺失的预期阶段标注"未找到"
  - 不阻止用户继续分析已存在的阶段
- **成功结果**：用户了解阶段完整性，可基于现有阶段继续
- **失败表现**：无
- **evidence 要求**：不需要
- **MVP 必须**：否（MVP 可选）

### ST-007 阶段命名异常处理

- **系统动作**：当阶段目录命名不符合预期模式时处理
- **系统必须**：
  - 仍将其作为候选阶段展示
  - 标注"命名异常"
  - 允许用户选择并分析
- **成功结果**：非标准命名的阶段仍可被分析
- **失败表现**：无
- **evidence 要求**：不需要
- **MVP 必须**：否（MVP 可选）

### ST-008 阶段为空处理

- **系统动作**：当阶段目录存在但无内容时处理
- **系统必须**：
  - 在阶段列表中以降级样式展示（灰色、禁用点击或点击后提示）
  - 提示"该阶段目录为空"
- **成功结果**：用户了解该阶段无内容可分析
- **失败表现**：无
- **evidence 要求**：不需要
- **MVP 必须**：是

## 输入

| 输入项 | 来源 | 类型 |
|--------|------|------|
| workspace_profile.json | story-open-workspace 输出 | 结构化数据 |
| 用户选中的阶段 | 用户点击 | UI 交互 |

## 输出

| 输出项 | 类型 | 说明 |
|--------|------|------|
| stage_context.json | 结构化数据 | 选中阶段的文件列表、外部依赖、上下文摘要 |
| 阶段概览面板 | UI 状态 | 阶段文件列表、分析按钮 |

## 异常 / 空状态

| 场景 | 处理 |
|------|------|
| 阶段目录不存在 | 提示"阶段目录已不存在，请重新打开项目" |
| 阶段目录不可读 | 提示"无法读取阶段目录"，允许重新选择 |
| 阶段无代码文件 | 提示"该阶段无可分析代码"，允许用户强制继续或选择其他阶段 |
| 阶段为空 | 在列表中禁用该阶段，点击时提示"该阶段为空" |
| 所有阶段都为空 | 提示"该项目所有阶段都为空"，建议检查项目结构 |

## 证据与追溯要求

- 阶段上下文中的每个文件必须包含 source path
- 外部依赖标识应包含引用位置（文件路径 + 行号范围）

## 不确定性表达要求

- 命名异常的阶段应标注 `uncertain`
- 阶段完整性判断（哪些阶段缺失）应作为不确定项展示
- 上游阶段接口约定的关联应标注 `inferred`（系统推断的关联关系）

## MVP 验收标准

- [ ] 阶段列表按自然顺序展示，包含文件数量统计
- [ ] 用户可单选一个阶段
- [ ] 选中阶段后系统验证其有效性
- [ ] 阶段上下文包含文件列表和外部依赖标识
- [ ] 阶段概览面板展示文件列表和"开始分析"按钮
- [ ] 空阶段在列表中有降级展示和恰当提示
- [ ] 阶段选择不触发任何写入操作

## 非目标

- 不支持多阶段同时选择
- 不做阶段间依赖关系的深度解析（留到 evidence 收集）
- 不做阶段正确性判断
