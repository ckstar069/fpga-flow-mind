# Story: 持久化与再次打开

---
status: draft
updated: 2026-06-11
---

## 用户目标

作为 FPGA 开发人员，我希望系统生成的理解产物能够被保存，并在下次打开同一项目时直接加载，避免每次都重新分析。

## 业务背景

大模型生成结构化理解需要时间和计算资源。用户可能需要多次查看同一个项目的分析结果，或在不同会话中继续追问。持久化可以节省时间并提供连续性体验。

## 前置条件

- ImplementationUnderstanding 已生成
- evidence_index 已建立
- workspace profile 已生成

## 触发入口

系统自动持久化（分析完成后），或用户手动触发保存。再次打开时，系统自动检测并提示加载。

## 主流程

1. 系统自动保存理解产物
2. 用户关闭并重新打开应用
3. 用户选择同一项目
4. 系统检测到已有持久化产物
5. 系统提示用户选择加载或重新分析
6. 用户选择加载，系统恢复之前的状态

## 功能点清单

### PS-001 系统自动持久化

- **系统动作**：在理解生成完成后自动保存产物
- **系统必须**：
  - 在理解生成成功完成后自动触发保存
  - 保存所有系统内产物到 app-owned 目录
  - 显示保存状态（成功/失败）
  - 保存失败时提示用户但不阻塞后续操作
- **成功结果**：产物已持久化
- **失败表现**：保存失败时提示"自动保存失败"，提供手动保存入口
- **evidence 要求**：不需要
- **MVP 必须**：是

### PS-002 系统内产物定义

- **系统动作**：定义需要持久化的系统内产物
- **系统必须**：持久化以下产物：
  - `workspace_profile.json` — 项目结构识别结果
  - `evidence_index.json` — 证据索引
  - `implementation_understanding.json` — 结构化理解产物
  - `visualization_spec.json` — 可视化规范数据（如有预计算）
  - `trace_index.json` — 追溯索引
  - `qa_history.json` — 问答历史（如有）
- **成功结果**：所有关键产物已保存
- **失败表现**：部分产物保存失败时记录日志
- **evidence 要求**：产物中的 source_path 应使用绝对路径
- **MVP 必须**：是

### PS-003 存储位置约束

- **系统动作**：确保存储位置不污染目标项目
- **系统必须**：
  - 所有产物存储在 app-owned 目录（如应用配置目录下的 `workspaces/`）
  - 或存储在临时目录（不推荐作为默认）
  - **绝不写入目标项目目录**（`fpga_project_*`）
  - 存储路径以 workspace 的绝对路径哈希或目录名作为子目录标识
- **成功结果**：目标项目目录无任何变化
- **失败表现**：尝试写入目标目录时应被拒绝并报错
- **evidence 要求**：不需要
- **MVP 必须**：是

### PS-004 再次打开时检测产物

- **系统动作**：用户选择同一项目时检测是否存在持久化产物
- **系统必须**：
  - 根据项目路径计算产物存储位置
  - 检查该位置是否存在有效的持久化产物
  - 如存在，提示"检测到已有分析结果，是否加载？"
  - 如不存在，进入正常的分析流程
- **成功结果**：用户可选择加载或重新分析
- **失败表现**：产物损坏时提示"已有分析结果损坏，建议重新分析"
- **evidence 要求**：不需要
- **MVP 必须**：是

### PS-005 加载持久化产物

- **系统动作**：加载之前保存的产物
- **系统必须**：
  - 读取所有产物文件
  - 验证产物完整性（检查必要字段是否存在）
  - 恢复 workspace profile、evidence_index、ImplementationUnderstanding
  - 恢复问答历史（如有）
  - 展示加载状态
- **成功结果**：用户可继续查看之前的分析结果
- **失败表现**：
  - 产物损坏：提示"加载失败，建议重新分析"
  - 部分产物缺失：提示"部分数据缺失，某些功能可能不可用"
- **evidence 要求**：加载后 evidence_index 必须完整可用
- **MVP 必须**：是

### PS-006 重新分析选项

- **用户动作**：用户选择重新分析而非加载旧产物
- **系统必须**：
  - 清除旧的持久化产物（或保留为备份）
  - 重新执行 evidence 收集和理解生成流程
  - 完成后自动保存新产物
- **成功结果**：用户获得最新的分析结果
- **失败表现**：清除旧产物失败时记录日志，继续重新分析
- **evidence 要求**：不需要
- **MVP 必须**：是

### PS-007 源码变化检测

- **系统动作**：检测目标项目的源码是否自上次分析后发生变化
- **系统必须**：
  - 对比持久化时记录的文件时间戳/哈希与当前文件状态
  - 如检测到变化，提示"源文件已变更，当前分析结果可能过时"
  - 提供"重新分析"建议
  - 仍允许用户查看旧结果（带过期提示）
- **成功结果**：用户了解分析结果的时效性
- **失败表现**：无法检测时标注"无法验证时效性"
- **evidence 要求**：不需要
- **MVP 必须**：否（MVP 可选，首次版本可仅支持手动重新分析）

### PS-008 产物版本兼容性

- **系统动作**：处理产物格式版本变化的情况
- **系统必须**：
  - 在产物中标注版本号
  - 如加载的产物版本与当前应用版本不兼容，提示"产物版本不兼容，建议重新分析"
  - 不尝试自动迁移不兼容的产物
- **成功结果**：版本不兼容时有清晰提示
- **失败表现**：无
- **evidence 要求**：不需要
- **MVP 必须**：否（MVP 可选，首次版本只有一个版本）

### PS-009 手动保存

- **用户动作**：用户手动触发保存
- **系统必须**：
  - 提供"保存分析结果"按钮或菜单项
  - 保存当前所有产物
  - 显示保存成功/失败提示
- **成功结果**：产物已手动保存
- **失败表现**：保存失败时提示原因
- **evidence 要求**：不需要
- **MVP 必须**：否（MVP 可选，自动保存已足够）

### PS-010 产物清理

- **用户动作**：用户删除旧项目的分析产物
- **系统必须**：
  - 提供管理界面列出所有已保存的分析产物
  - 允许用户选择删除某个项目的产物
  - 删除时仅删除 app-owned 目录中的内容
- **成功结果**：旧产物被清理
- **失败表现**：删除失败时提示原因
- **evidence 要求**：不需要
- **MVP 必须**：否（MVP 可选）

## 输入

| 输入项 | 来源 | 类型 |
|--------|------|------|
| workspace_profile | story-open-workspace 输出 | 结构化数据 |
| evidence_index | story-collect-evidence 输出 | 结构化数据 |
| ImplementationUnderstanding | story-generate-understanding 输出 | 结构化数据 |
| 用户选择 | 用户交互 | 加载/重新分析 |

## 输出

| 输出项 | 类型 | 说明 |
|--------|------|------|
| 持久化产物文件 | 文件系统 | app-owned 目录下的 JSON 文件 |
| 加载状态 | UI 状态 | 加载成功/失败/过期的提示 |

## 异常 / 空状态

| 场景 | 处理 |
|------|------|
| 产物保存失败 | 提示"保存失败"，提供手动保存入口 |
| 产物加载失败 | 提示"加载失败，建议重新分析" |
| 产物损坏 | 提示"产物损坏，建议重新分析" |
| 存储空间不足 | 提示"存储空间不足，无法保存" |
| 源码已变更 | 提示"源文件已变更，结果可能过时"，建议重新分析 |
| 产物版本不兼容 | 提示"版本不兼容，建议重新分析" |

## 证据与追溯要求

- 持久化产物中的 source_path 应使用绝对路径，以便重新加载时仍可定位
- evidence_index 中的 evidence_id 应在重新加载后仍然有效

## 不确定性表达要求

- 源码变更检测的不确定性应标注（如"可能已变更"）
- 产物加载失败时应说明失败原因

## MVP 验收标准

- [ ] 分析完成后自动保存产物到 app-owned 目录
- [ ] 产物包含 workspace_profile、evidence_index、ImplementationUnderstanding
- [ ] 不写入目标项目目录
- [ ] 再次打开同一项目时检测已有产物
- [ ] 用户可选择加载或重新分析
- [ ] 加载后恢复之前的状态（视图、evidence、问答）
- [ ] 产物损坏时有恰当提示

## 非目标

- 不做自动增量更新（源码变更后需手动重新分析）
- 不做云端同步
- 不做多设备共享
- 不做版本历史管理
- 不做自动备份清理策略
