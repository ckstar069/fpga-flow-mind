# Story: 围绕节点追问

---
status: draft
updated: 2026-06-11
---

## 用户目标

作为 FPGA 开发人员，我希望围绕图中的某个节点或结论继续提问，以便深入理解具体实现细节。

## 业务背景

图和 evidence 面板提供了阶段实现的概览和证据，但用户往往有更深入的问题：某个信号的具体位宽是多少、某个公式中的参数从何而来、某个模块与前序阶段的关系是什么。系统需要支持基于已有 evidence 的追问。

## 前置条件

- 用户正在查看某类视图或 evidence 面板
- evidence_index 已建立
- ImplementationUnderstanding 已生成

## 触发入口

用户在节点详情面板或 evidence 面板中点击"追问"按钮，或在问答面板中直接输入问题。

## 主流程

1. 用户触发追问（选择节点或输入问题）
2. 系统构建问答上下文
3. 系统调用大模型/Agent 生成回答
4. 系统进行回答 grounding 检查
5. 系统展示回答

## 功能点清单

### QA-001 触发追问

- **用户动作**：用户在节点详情面板中点击"追问"按钮，或在问答面板中输入问题
- **系统必须**：
  - 记录当前追问的上下文（当前阶段、选中节点、相关 evidence）
  - 打开或聚焦问答面板
  - 如用户点击"追问"按钮，预填充问题上下文（如"关于模块 X："）
- **成功结果**：问答面板打开，用户可输入问题
- **失败表现**：无上下文时提示"请先选择一个节点或阶段"
- **evidence 要求**：不需要
- **MVP 必须**：是

### QA-002 问答上下文构建

- **系统动作**：为模型构建包含当前上下文的问答 prompt
- **系统必须**：
  - 包含当前阶段信息（stage_id、阶段摘要）
  - 包含选中节点的信息（名称、类型、description、evidence_refs）
  - 包含相关的 evidence items（代码片段、文档内容）
  - 明确约束：回答必须基于提供的 evidence，不得编造
- **成功结果**：生成结构化的问答上下文
- **失败表现**：上下文构建失败时提示"无法构建问答上下文"
- **evidence 要求**：上下文中的 evidence 必须来自 evidence_index
- **MVP 必须**：是

### QA-003 追问绑定阶段上下文

- **系统动作**：确保每个追问都绑定到当前阶段
- **系统必须**：
  - 问答面板标题显示当前阶段名称
  - 每个问题自动关联当前 stage_id
  - 用户切换阶段时，问答历史保留但新问答关联新阶段
- **成功结果**：用户清楚当前问答属于哪个阶段
- **失败表现**：无
- **evidence 要求**：不需要
- **MVP 必须**：是

### QA-004 追问绑定节点上下文

- **系统动作**：确保每个追问都绑定到选中的节点（如用户通过节点触发）
- **系统必须**：
  - 记录用户当前选中的节点
  - 将节点信息（名称、类型、evidence_refs）纳入问答上下文
  - 在问答历史中标注该问题关联的节点
- **成功结果**：问答围绕具体节点展开
- **失败表现**：无节点上下文时（用户在全局问答面板提问），使用阶段级上下文
- **evidence 要求**：节点信息必须包含 evidence_refs
- **MVP 必须**：是

### QA-005 回答生成

- **系统动作**：调用大模型/Agent 基于上下文和 evidence 生成回答
- **系统必须**：
  - 将问答上下文提交给模型
  - 要求模型回答基于提供的 evidence
  - 要求模型在回答中引用 evidence_ids
  - 要求模型对不确定的内容标注为 `unknown`
- **成功结果**：模型返回带 evidence 引用的回答
- **失败表现**：
  - 模型调用失败：提示"问答服务暂不可用"
  - 返回格式错误：提示"回答格式异常"
- **evidence 要求**：回答必须引用 evidence_ids
- **MVP 必须**：是

### QA-006 回答引用 evidence_id

- **系统动作**：确保回答中的每个结论都引用 evidence
- **系统必须**：
  - 回答中的每个 claim 必须关联至少一个 evidence_id
  - evidence_id 必须是 evidence_index 中真实存在的 id
  - 引用格式清晰（如"根据证据 EV-001"或超链接形式）
- **成功结果**：用户可验证回答的 evidence 来源
- **失败表现**：无 evidence 支撑的回答标注为 `unknown`
- **evidence 要求**：每个 claim 的 evidence_refs 必须可验证
- **MVP 必须**：是

### QA-007 证据不足时回答 unknown

- **系统动作**：当用户问题缺乏证据支撑时处理
- **系统必须**：
  - 明确回答"根据当前证据，无法确定该问题"
  - 说明缺乏证据的原因（如"未找到相关信号定义"）
  - 不编造答案
  - 可提供建议："您可以检查文件 X 的第 Y 行"
- **成功结果**：用户了解问题无法回答的原因
- **失败表现**：无
- **evidence 要求**：unknown 回答应说明涉及的 source path（如可推断）
- **MVP 必须**：是

### QA-008 不回答无关问题

- **系统动作**：当用户问题与当前阶段无关时处理
- **系统必须**：
  - 检测问题是否与当前阶段或已收集 evidence 相关
  - 如不相关，回答"该问题与当前阶段无关，请围绕当前阶段提问"
  - 不基于模型的训练知识回答无关问题
- **成功结果**：问答保持在当前阶段上下文中
- **失败表现**：无
- **evidence 要求**：不需要
- **MVP 必须**：是

### QA-009 不替用户判断正确/错误

- **系统动作**：当用户问"这个实现对吗"或"这里有问题吗"时处理
- **系统必须**：
  - 回答"我只能基于证据描述实现内容，不做正确性判断"
  - 提供相关的 evidence 供用户自行判断
  - 不给出"正确"或"错误"的结论
- **成功结果**：用户了解系统的定位边界
- **失败表现**：无
- **evidence 要求**：仍应提供相关的 evidence 引用
- **MVP 必须**：是

### QA-010 回答 grounding 检查

- **系统动作**：验证回答中的 claim 是否与 evidence 一致
- **系统必须**：
  - 检查回答引用的 evidence_ids 是否存在于 evidence_index
  - 检查回答描述是否与 evidence 内容一致
  - 对不一致的 claim 标注为 `conflicting` 或降级
- **成功结果**：回答经过 grounding 验证
- **失败表现**：grounding 失败时标注"部分回答未通过证据验证"
- **evidence 要求**：grounding 基于 evidence_index 实际内容
- **MVP 必须**：是

### QA-011 问答历史展示

- **系统动作**：在问答面板中展示历史问答记录
- **系统必须**：
  - 以对话形式展示问答历史（用户问题 + 系统回答）
  - 每个回答展示引用的 evidence_ids
  - 标注每个回答的置信度
  - 支持滚动浏览历史
- **成功结果**：用户可回顾之前的问答
- **失败表现**：无历史时显示"开始提问"
- **evidence 要求**：历史中的回答必须保留 evidence 引用
- **MVP 必须**：是

## 输入

| 输入项 | 来源 | 类型 |
|--------|------|------|
| 用户问题 | 用户输入 | 自然语言文本 |
| 当前阶段 | 系统状态 | stage_id + 阶段上下文 |
| 选中节点 | 系统状态 | 节点信息 + evidence_refs |
| evidence_index | story-collect-evidence 输出 | 结构化数据 |
| ImplementationUnderstanding | story-generate-understanding 输出 | 结构化数据 |

## 输出

| 输出项 | 类型 | 说明 |
|--------|------|------|
| 系统回答 | 自然语言文本 | 基于 evidence 的回答，附带 evidence 引用 |
| 问答历史 | UI 状态 | 对话形式的问答记录 |

## 异常 / 空状态

| 场景 | 处理 |
|------|------|
| 用户问题为空 | 提示"请输入问题" |
| evidence_index 为空 | 提示"暂无证据，请先收集证据" |
| 模型调用失败 | 提示"问答服务暂不可用，请稍后重试" |
| 回答无 evidence 支撑 | 标注为 `unknown`，说明原因 |
| 问题与当前阶段无关 | 提示"请围绕当前阶段提问" |
| 用户问正确性问题 | 提示"不做正确性判断，仅提供证据描述" |

## 证据与追溯要求

- 回答中的每个 claim 必须关联至少一个 evidence_id
- evidence_id 必须是 evidence_index 中真实存在的 id
- 用户应能通过 evidence_id 追溯到 source_path 和 line_range

## 不确定性表达要求

- 证据不足的回答明确标注 `unknown`
- 推断性回答标注 `inferred` 并说明依据
- 冲突证据的回答标注 `conflicting`
- 不将 `inferred` 或 `unknown` 呈现为 `confirmed`

## MVP 验收标准

- [ ] 用户可通过节点详情面板触发追问
- [ ] 追问绑定当前阶段和节点上下文
- [ ] 回答引用 evidence_ids
- [ ] 证据不足时回答 `unknown`，不编造
- [ ] 不回答与当前阶段无关的问题
- [ ] 不替用户判断正确/错误
- [ ] 回答经过 grounding 检查
- [ ] 问答历史以对话形式展示
- [ ] 追问不触发任何写入操作

## 非目标

- 不做跨阶段问答（单阶段内问答）
- 不做代码自动生成或修复建议
- 不做开放式闲聊
- 不做多轮复杂推理（MVP 支持单轮或简单多轮）
